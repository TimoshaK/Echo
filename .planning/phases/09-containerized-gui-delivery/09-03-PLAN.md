Entrypoint defaults (`docker/entrypoint.sh`):
- Xvfb display `:99`, screen `1440x900x24`
- app: `python -m echo`
- x11vnc loopback-only on `5900`, `-nopw` unless `VNC_PASSWORD` is set
- websockify `--web /usr/share/novnc/` on `6080` → `localhost:5900`
- ENV overrides: `DISPLAY_NUM`, `SCREEN`, `VNC_PORT`, `NOVNC_PORT`, `VNC_PASSWORD`

Dockerfile: `EXPOSE 6080`, `ENTRYPOINT ["/usr/local/bin/entrypoint.sh"]`, CPU-only image.
Browser URL: `http://localhost:6080/vnc.html` (optionally `?autoconnect=1&resize=scale`).

Config contract (`echo/config.py`):
- default path `/app/app_config.json` (repo root inside the image)
- `ECHO_CONFIG_PATH` overrides it; for a container use a **directory** mount:
  `-v "<host_dir>:/config" -e ECHO_CONFIG_PATH=/config/app_config.json`
- **Do NOT document a single-file mount** `-v app_config.json:/app/app_config.json`: `os.replace`
  onto a bind-mounted file fails with `EBUSY` (reproduced), so "Save Settings" would break.

Whisper model cache (verified from the `openai-whisper==20250625` sdist): `~/.cache/whisper`
→ `/root/.cache/whisper` in the container.

Existing BUILD.md sections to preserve (behavior unchanged): "How dependencies are installed"
(CPU-wheel-first + `--require-hashes`, the `triton` Linux-marker note, the torch-without-hash
limitation) and "Regenerating the locks" (Windows `pip-compile` command and the `python:3.14` Linux
CPU-index recipe). Keep their technical content intact.

Documentation encoding convention (Phase 8): `README.md` and `SETUP_GUIDE.txt` are **UTF-8 with CRLF
only** (0 bare LF). Preserve both on every edit.

   ```
   docker run --rm -p 127.0.0.1:6080:6080 -v "${PWD}/config:/config" -e ECHO_CONFIG_PATH=/config/app_config.json -v echo-whisper:/root/.cache/whisper -v "${PWD}/audio:/root/audio" echo:cpu
   ```

   Then: open `http://localhost:6080/vnc.html` (optionally `?autoconnect=1&resize=scale`).

4. **Port binding and security** — explain that `-p 127.0.0.1:6080:6080` keeps the desktop
   machine-local; exposing on the LAN (`-p 6080:6080`) is opt-in and should be paired with
   `-e VNC_PASSWORD=<password>`. State that noVNC/websockify here is plain `ws://` (no TLS) and that
   TLS should be terminated by a reverse proxy if needed. Mention x11vnc is bound to loopback inside
   the container, so raw port `5900` is not reachable.

5. **Configuration (corporate https LLM)** — document the mounted-config contract:
   - the config file is `app_config.json`; put it in a host directory and mount that directory;
   - **do not** mount the file itself: a single-file bind mount breaks the app's atomic save
     (`os.replace` → `EBUSY`), so "Save Settings" fails. Mount the directory instead.
   - provide the example JSON payload from `<interfaces>` (https `base_url`);
   - state that `base_url` must be `https://` — the app rejects other schemes (SEC-02);
   - the API key must never be baked into the image (`.dockerignore` excludes `app_config.json`).

6. **Audio and results** — the file dialogs start at `/root`; mount a host directory at
   `/root/audio` (read-write) and navigate to `/root/audio`. State that the mount must be writable to
   save `.txt`/`.srt`.

7. **Whisper model cache** — mount `/root/.cache/whisper` (named volume `echo-whisper` or a host dir)
   to avoid re-downloading the `base` model (~142 MB) and to run without internet once populated.

8. **Deploy to another PC** — two documented paths, with the literals `docker save` and `docker load`:
   ```
   docker save echo:cpu -o echo-cpu.tar
   docker load -i echo-cpu.tar
   ```
   and the registry alternative (`docker tag` + `docker push` + `docker pull`). Note the tar is
   multi-GB (use a drive with space; `A:` had 101 GB free at research time) and that the target PC
   needs Docker Desktop plus the same mounts.

9. **Optional GPU** — state plainly that the image is CPU-only. A CUDA host needs
   `--gpus all` + `nvidia-container-toolkit` and the `requirements-cuda.txt` lock; this is out of
   scope for this image.

10. **Debugging** — `docker run --rm --entrypoint bash echo:cpu` and `docker logs <name>`; note the
    app is the lifecycle anchor so a startup crash exits the container with the traceback in the logs.

11. **Keep** the existing "How dependencies are installed" and "Regenerating the locks" sections
    (content preserved).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Documentation → operator behavior | The docs tell the operator how to expose the desktop and where to put the API key |
| Host config directory → container | The documented mount is the config trust boundary |
| Image artifact → second PC | `docker save`/`load` moves the whole image between machines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04 | Information Disclosure | Docs instruct baking the key into the image or committing it | mitigate | BUILD.md explicitly forbids baking `app_config.json`; documents a host-directory mount; `tests/test_docker_docs.py` asserts `ECHO_CONFIG_PATH=/config/app_config.json` is present |
| T-09-13 | Elevation of Privilege | Docs encourage `-p 6080:6080` on `0.0.0.0` with no password, exposing an unauthenticated desktop | mitigate | Docs default to `-p 127.0.0.1:6080:6080`; LAN exposure is opt-in and paired with `-e VNC_PASSWORD`; the plain `ws://` limitation is stated |
| T-09-14 | Spoofing | A reader copies a `http://` corporate `base_url` and bypasses the security posture | mitigate | Docs state `https://` is required and that the app rejects other schemes (SEC-02) |
| T-09-15 | Repudiation | Operator cannot tell whether a startup failure is the app or the VNC stack | mitigate | The debugging section explains that the app is the lifecycle anchor and that `docker logs` shows the traceback |
</threat_model>
