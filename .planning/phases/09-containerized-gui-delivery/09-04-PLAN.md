This is the real proof of CNTR-01 and CNTR-02. Expect the first build to take several minutes (apt +
torch + the lock install). Use a generous timeout. If `echo:cpu` already exists, the build reuses
cached layers.

1. Build:
   ```powershell
   docker build -t echo:cpu .
   ```

2. Create a scratch host config directory with a dummy corporate https config (never the real key):
   ```powershell
   New-Item -ItemType Directory -Force -Path A:\gsd-tmp\echo-config | Out-Null
   Set-Content -Path A:\gsd-tmp\echo-config\app_config.json -Value '{"llm":{"api_key":"sk-test-000","base_url":"https://llm.corp.example/v1","model":"gpt-4o-mini","enabled":true,"summary_preset":"free"}}' -Encoding ascii
   ```

3. Start the container detached, loopback-bound, with the config **directory** mounted:
   ```powershell
   docker rm -f echo-vnc 2>$null
   docker run -d --rm -p 127.0.0.1:6080:6080 --name echo-vnc -v "A:\gsd-tmp\echo-config:/config" -e ECHO_CONFIG_PATH=/config/app_config.json echo:cpu
   ```
   Wait a few seconds for Xvfb + Tk to come up.

4. Confirm the app is actually alive (not a VNC port serving an empty desktop):
   ```powershell
   docker logs echo-vnc
   docker exec echo-vnc pgrep -f "python -m echo"
   ```
   Expected: `docker logs` shows no Python traceback, and `pgrep` prints a PID.

5. Run the ASCII HTTP + WebSocket probe:
   ```powershell
   py -3 -c "import socket,base64,os,time,urllib.request as u
url='http://127.0.0.1:6080/vnc.html'
for _ in range(60):
    try:
        if u.urlopen(url,timeout=2).status==200:
            break
    except Exception:
        time.sleep(1)
else:
    raise SystemExit('vnc.html did not return 200')
print('VNC_HTML_200')
assert u.urlopen('http://127.0.0.1:6080/core/rfb.js',timeout=5).status==200
print('CORE_200')
k=base64.b64encode(os.urandom(16)).decode()
r=('GET /websockify HTTP/1.1\r\nHost: 127.0.0.1:6080\r\nUpgrade: websocket\r\nConnection: Upgrade\r\nSec-WebSocket-Key: '+k+'\r\nSec-WebSocket-Version: 13\r\n\r\n')
s=socket.create_connection(('127.0.0.1',6080),timeout=5)
s.sendall(r.encode())
resp=s.recv(1024).decode('latin-1')
s.close()
assert '101 Switching Protocols' in resp,resp
print('WS_101')
print('E2E_OK')"
   ```
   Expected: `VNC_HTML_200`, `CORE_200`, `WS_101`, `E2E_OK`.

**If the probe fails:** capture `docker logs echo-vnc` and the output of `docker exec echo-vnc bash -lc
"ls -l /tmp/.X11-unix; cat /tmp/x11vnc.log 2>/dev/null | tail -20"` before reporting. Do not change the
source to make the probe pass — a runtime failure is a finding, not something to paper over.

Leave the container running for Task 2.

   ```powershell
   py -3 -c "import json,pathlib;p=pathlib.Path(r'A:\gsd-tmp\echo-config\app_config.json');d=json.loads(p.read_text('utf-8'));assert d['llm']['api_key']=='sk-round-trip-123',d;print('HOST_MOUNT_UPDATED')"
   ```
   Expected: `HOST_MOUNT_UPDATED`.

3. **https-only still enforced inside the container** (preserve SEC-02):
   ```powershell

    validate_base_url('http://llm.corp.example/v1')
    raise SystemExit('http accepted - SEC-02 broken')

print('HTTPS_ACCEPTED')"
   ```

   Then delete the tar to reclaim space:

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → container noVNC | Untrusted network input crosses into the runtime under test |
| Host config directory → container | The config trust boundary exercised by the round-trip probe |
| Image tar → second PC | The deployment artifact crossing machines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Spoofing / Information Disclosure | noVNC exposed without authentication during the verification run | mitigate | The run binds `127.0.0.1:6080:6080` (localhost only); the container is `--rm` and stopped at the end; the operator is told to use a private `C:\echo-config` directory |
| T-09-06 | Tampering | `docker save`/`load` silently yielding a different or corrupt image | mitigate | Task 2 re-lists `docker images echo` after `docker load` and requires `echo:cpu` to be present; the tar lives on `A:` where there is space |
| T-09-16 | Information Disclosure | A verification probe reading or printing the operator's real API key | mitigate | All probes use a scratch config under `A:\gsd-tmp` with a dummy `sk-test-000` key; the real `app_config.json` is never mounted or printed by this plan |
| T-09-17 | Elevation of Privilege | Container escape via the mounted config/audio directories | accept | Standard bind-mount risk of running a local desktop tool in Docker; the container is not privileged and no host socket is mounted; documented for the operator |
| T-09-18 | Denial of Service | `docker save` filling the system drive (multi-GB tar) | mitigate | The tar is written to `A:\gsd-tmp` and deleted immediately after the round-trip |
| T-09-19 | Tampering | A verification task "fixing" a runtime failure to make itself pass | mitigate | Explicitly prohibited in Task 1; a failed probe must be reported as a finding, not patched inside the verification plan |
</threat_model>
