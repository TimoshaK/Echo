<objective>
Make the app's config location overridable via `ECHO_CONFIG_PATH` so a **directory** bind mount
(`-v <host_dir>:/config` + `ECHO_CONFIG_PATH=/config/app_config.json`) works with the existing atomic,
owner-only config writer — without changing the default path or the https-only endpoint policy.

Purpose: CNTR-03. A single-file bind mount of `app_config.json` makes `os.replace` fail with `EBUSY`
(reproduced in research), so the corporate endpoint could be read but never saved from the GUI. A
directory mount fixes that, and requires the app to be told where the file is.

Output: a small, behavior-preserving change to `echo/config.py` plus unit tests. No Docker files here
(this plan is independent of Plan 09-01).
</objective>

them.

```python
def resolve_config_path(env: Mapping[str, str] | None = None) -> Path:
    """Вернуть путь к app_config.json.

    Приоритет — переменная окружения ECHO_CONFIG_PATH: в контейнере репозиторий
    не является монтируемым томом, и entrypoint указывает на смонтированный
    каталог (/config/app_config.json). Без переменной путь прежний — корень
    репозитория, — поэтому REFR-03 сохраняется.
    """
    if env is None:
        env = os.environ
    override = env.get("ECHO_CONFIG_PATH")
    if override and override.strip():
        return Path(override).expanduser()
    # D-01: app_config.json lives in the REPOSITORY ROOT — one level above the echo/ package.
    # Do NOT use Path(__file__).parent here: that resolves to echo/app_config.json, which does
    # not exist, and load_config() would silently fall back to DEFAULT_CONFIG (empty API key),
    # breaking REFR-03 with no visible error.
    return Path(__file__).resolve().parent.parent / "app_config.json"


CONFIG_PATH = resolve_config_path()
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host mount → container config file | The only config source crossing into the container |
| Env var → config path | `ECHO_CONFIG_PATH` decides which file the app trusts as its settings |
| Config value → outbound https request | `base_url`/`api_key` still cross into the LLM request path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03 | Tampering | Single-file bind mount makes the atomic writer fail (`os.replace` → `EBUSY`), risking partial/lost config or a failed save | mitigate | The override exists specifically to support a **directory** mount; `_atomic_write_secure` is unchanged (same-directory mkstemp + `os.replace`); research reproduces the EBUSY failure and the directory-mount success |
| T-09-10 | Spoofing | A wrong `ECHO_CONFIG_PATH` could point the app at an attacker-controlled file | accept | The env var is set by the container operator at `docker run` time, i.e. the same trust level as the file itself; no untrusted input reaches it |
| T-09-11 | Elevation of Privilege | The mount could be used to bypass the https-only policy | mitigate | `validate_base_url` (`echo/llm_client.py`) is explicitly untouched and still called on every request; the plan's verify asserts it remains; `config.py` never validates or rewrites `base_url` |
| T-09-12 | Information Disclosure | The override makes the app write the API key to a mounted, possibly world-readable directory | mitigate | `save_config` keeps `chmod 0600` on the mounted file; docs (Plan 09-03) require a private host directory |
</threat_model>
