<objective>
Add a second lock that installs the CUDA build of PyTorch (`torch==2.14.0+cu130`) from the PyTorch
cu130 wheel index, with hashes on every package.

Purpose: SUP-02. The CPU lock deliberately pins `torch==2.14.0` (the PyPI CPU wheel). A user with an
NVIDIA GPU needs the `+cu130` build, and that build is not on PyPI — it lives on
`https://download.pytorch.org/whl/cu130`. It must therefore be pinned and hashed separately.

Output: `requirements-cuda.in` (input) and `requirements-cuda.txt` (compiled CUDA lock).

**This plan exists because of a verified trap.** The naive
`pip-compile --generate-hashes --extra-index-url https://download.pytorch.org/whl/cu130` **fails**:
pip-tools sources hashes from the PyPI JSON API, which has no `2.14.0+cu130` release, so it falls back
to downloading every candidate wheel — and because `resolve_hashes()` runs under
`allow_all_wheels()`, that is **all 24** cu130 wheels (tens of GB). Observed failure:
`OSError(28, 'No space left on device')`. The extra index also mirrors `numpy`/`tqdm`/`sympy`/… so
those get pulled into hashing too. See `08-RESEARCH.md` for the full derivation. The fix — seeding the
output file and letting `--reuse-hashes` short-circuit every lookup — is verified to complete with
**zero wheel downloads**.
</objective>

<shell_quoting_rule>
**PowerShell quoting is treacherous here — follow this form for every Python probe in this plan.**

PowerShell 5.1 strips embedded double quotes when it passes a single-quoted argument to a native
`.exe`, and a `\"` inside a double-quoted argument terminates the PowerShell string early. Use this
shape, verified working:

- Outer: a **double-quoted** PowerShell string, which may span multiple lines.
- Inner: **single quotes** for every Python string literal.
- Never write a literal `"` in the Python source — use `chr(34)`.
- Never write a literal backslash in the Python source — use `chr(92)`.

Working example (verified):

```powershell
py -3 -c "import pathlib
t=pathlib.Path('requirements.txt').read_text('utf-8')
assert 'torch==2.14.0 ' + chr(92) in t
print('OK')"
```

```powershell
py -3 -c "import pathlib,re,urllib.request
idx='https://download.pytorch.org/whl/cu130'
ver='2.14.0+cu130'
enc=ver.replace('+','%2B')
html=urllib.request.urlopen(idx+'/torch/',timeout=90).read().decode('utf-8','replace')
hashes=sorted(set(re.findall('torch-'+re.escape(enc)+'-[^'+chr(34)+'#]+[.]whl#sha256=([0-9a-f]{64})',html)))
assert len(hashes)==24,len(hashes)
cpu=pathlib.Path('requirements.txt').read_text('utf-8').splitlines()
out=[]
i=0
while i<len(cpu):
    if cpu[i].startswith('torch=='):
        out.append('torch=='+ver+' '+chr(92))
        for h in hashes:
            out.append('    --hash=sha256:'+h+' '+chr(92))
        j=i+1
        while j<len(cpu) and cpu[j].startswith('    --hash='):
            j+=1
        while j<len(cpu) and cpu[j].startswith('    #'):
            out.append(cpu[j]); j+=1
        i=j
        continue
    out.append(cpu[i]); i+=1
seed=chr(10).join(['--extra-index-url '+idx]+out)+chr(10)
pathlib.Path('requirements-cuda.txt').write_text(seed,encoding='utf-8',newline='')
pathlib.Path('requirements-cuda.in').write_text('--extra-index-url '+idx+chr(10)+'openai-whisper==20250625'+chr(10)+'torch=='+ver+chr(10)+'numpy==2.4.4'+chr(10)+'tqdm==4.70.0'+chr(10),encoding='utf-8',newline='')
print('seeded hashes:',len(hashes))"
```

**Why the encoding dance:** the version must be matched as `2.14.0%2Bcu130` (URL-encoded). The script
builds that with `ver.replace('+','%2B')` and feeds it through `re.escape`, so no literal backslash

terminate the PowerShell string) and `chr(92)` for `\` (which PowerShell mangles).

**Why the trailing `# via` lines are copied:** pip-tools preserves the provenance annotation, and the
reused seed should look like its final form so the diff after Task 2 is only the header.

**Do NOT** hand-write the 24 hashes or paste them from documentation — always re-fetch them. The
values are stable, but sourcing them programmatically is what makes this reproducible.

**Avoid:** adding `--extra-index-url` to `requirements-cuda.in` a second time on the command line, or
omitting it from the `.in` file. It belongs in the `.in` file only; `--emit-index-url` (default on)
will carry it into the output.

`existing_pins` and, with `--reuse-hashes` (default on, but pass it explicitly so the header records
it), `LocalRequirementsRepository.get_hashes` returns the seeded hashes for every package instead of
downloading candidates. Without it, pip-tools downloads all 24 cu130 torch wheels plus every mirrored
`numpy`/`tqdm`/`sympy`/… wheel.

**`--emit-index-url` must stay at its default (on).** That is what writes the
`--extra-index-url https://download.pytorch.org/whl/cu130` line into the lock so
`pip install --require-hashes -r requirements-cuda.txt` can find the `+cu130` wheel. Do **not** pass
`--no-emit-index-url` here (that flag belongs to Plan 08-01's pure-PyPI locks).

`--allow-unsafe` and `--strip-extras` match Plan 08-01 so both locks share the same package set and
`setuptools` stays pinned (required by `torch`'s `Requires-Dist`).

```powershell
py -3 -c "import pathlib,re
def parse(p):
    d={}
    cur=None
    for l in pathlib.Path(p).read_text('utf-8').splitlines():
        m=re.match('^([a-z0-9._-]+)==([^ ]+)',l)
        if m:
            cur=m.group(1)
            d[cur]=(m.group(2),set())
            continue
        m2=re.match('^    --hash=sha256:([0-9a-f]{64})',l)
        if m2 and cur:
            d[cur][1].add(m2.group(1))
    return d
a=parse('requirements.txt')
b=parse('requirements-cuda.txt')
assert set(a)==set(b),set(a)^set(b)
for k in a:
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `download.pytorch.org/whl/cu130` → local environment | Second, non-PyPI artifact source; untrusted |
| `requirements-cuda.txt` → `pip install --require-hashes` | The lock is the enforcement contract for the CUDA install path |
| Mirrored packages (`numpy`, `tqdm`, `sympy`, …) served from two indexes | Ambiguous provenance; either index can satisfy the requirement |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-03 | Tampering | `torch==2.14.0+cu130` wheel from the PyTorch index | mitigate | All 24 index-published sha256 hashes are embedded in the lock; Task 3 re-fetches the live index and asserts set equality, so a silently rotated or substituted wheel fails the install |
| T-08-11 | Spoofing | Dependency confusion via `--extra-index-url` — a malicious `torch==2.14.0+cu130` published on PyPI could be selected because the lock searches both indexes | mitigate | Hash-checking mode restricts acceptable archives to the hashed set; a foreign wheel has a different digest and is rejected. Verified in `08-RESEARCH.md` that PyPI-only hashes plus the extra index still install correctly, and that mirrored wheels are byte-identical |
| T-08-12 | Denial of Service | pip-tools downloading all 24 cu130 wheels (~tens of GB) and exhausting the disk | mitigate | Seed + `--reuse-hashes` short-circuit every hash lookup (verified: zero downloads, exit 0); temp dir pinned to a ≥10 GB drive; Task 2 instructs the executor to stop immediately if `Downloading` lines appear |
| T-08-13 | Tampering | Non-torch package diverging between the two locks (one of them silently wrong) | mitigate | Task 3 asserts version **and** hash-set equality for every non-torch package |
| T-08-14 | Repudiation | CUDA lock regenerated with an untraceable or incomplete command | mitigate | `CUSTOM_COMPILE_COMMAND` records the full `--generate-hashes --reuse-hashes` invocation in the header; acceptance criteria assert it is present and that no spurious `--no-index` appears |
| T-08-15 | Elevation of Privilege | Malicious build backend executing at install time | accept | The CUDA lock contains no sdists — `openai-whisper` is the only sdist in the tree and it is built in the CPU-lock path. Residual risk is documented for the CPU lock in Plan 08-04's docs task |
