<objective>
Convert `requirements.txt` from a hand-written 4-line pin list into a `pip-tools` compiled lock that
pins every direct **and transitive** dependency with sha256 hashes, and add a matching dev-tooling
lock.

Purpose: SUP-01 and the lock half of SUP-05. A 4-line pin list leaves ~20 transitive packages
(`numba`, `tiktoken`, `requests`, `sympy`, `jinja2`, …) unpinned and unhashed — that is the exact
supply-chain gap this phase closes. Hashes make the tree tamper-evident: a substituted or corrupted
artifact fails the install instead of executing.

Output: `requirements.in`, `requirements.txt` (compiled CPU lock), `requirements-dev.in`,
`requirements-dev.txt` (compiled dev lock).
</objective>

`.exe`, and it mangles backslashes inside double-quoted strings. Use this shape, verified working:

- Inner: **single quotes** for every Python string literal.


**Why each flag is mandatory (do not drop any):**

- `--generate-hashes` — the point of the phase. This works without downloads because pip-tools reads
  digests from the **PyPI JSON API** for every release file of a pure-PyPI lock.
- `--allow-unsafe` — **mandatory, easy to miss.** `torch` declares `Requires-Dist: setuptools>=77.0.3`.
  Without this flag pip-tools omits `setuptools` from the output (it is classified "unsafe") and
  `pip install --require-hashes` then fails with *"Hashes are required for all dependencies"*.
- `--strip-extras` — emits one line per distribution instead of `pkg[extra]==x` lines.
- `--no-emit-index-url` / `--no-emit-trusted-host` — both locks are pure PyPI; emitting an index line
  would bake an environment-specific URL into the lock.
- `CUSTOM_COMPILE_COMMAND` — **required for a truthful header.** pip-tools' `get_compile_command()`
  records every plain flag unconditionally (`piptools/utils.py:379-388`), so the auto-generated header
  always contains a bogus `--no-index` even though it was never passed. Setting this env var replaces
  the header with an accurate, reproducible command.

**Do NOT pass `--extra-index-url` here.** Adding the PyTorch index would make pip-tools pull mirrored
`numpy`/`tqdm`/`sympy`/… copies into hash computation and start downloading wheels. That index belongs
only to Plan 08-02's CUDA lock.

**Expected result for `requirements.txt`:** 697 lines, 24 packages, **634** `--hash=sha256:` lines, a
clean header recording the command above, and the four direct pins unchanged. Package set (exact):
`certifi, charset-normalizer, colorama, filelock, fsspec, idna, jinja2, llvmlite, markupsafe,
more-itertools, mpmath, networkx, numba, numpy, openai-whisper, regex, requests, sympy, tiktoken,
torch, tqdm, typing-extensions, urllib3, setuptools` — with `setuptools==84.0.0` in a trailing
"unsafe packages" block.

**If pip-tools rewrites any of the four direct pins to a different version → STOP.** That is a
contract break; report it instead of continuing.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI index → local environment | Untrusted artifact source; every wheel/sdist crosses this boundary during install |
| `requirements*.in` → `requirements*.txt` | The hand-written input is trusted; the compiled lock is the artifact that must be complete |
| `requirements*.txt` → `pip install --require-hashes` | The lock is the enforcement contract; an unhashed entry silently disables protection for that package |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `requirements.txt` (transitive deps) | mitigate | `--generate-hashes` pins all 24 direct+transitive packages with sha256; Task 3 negative control proves a tampered hash is rejected |
| T-08-02 | Tampering | Unhashed requirement slipping into the lock | mitigate | Task 3 structural probe asserts every requirement line ends with `\` and is immediately followed by `--hash=sha256:`; `--require-hashes` turns a missing hash into a hard install error |
| T-08-07 | Elevation of Privilege | `pip-tools` / `pip-audit` / `pyinstaller` installed unpinned at bootstrap | accept | Bootstrap paradox: the tool that generates the lock cannot itself be locked first. Mitigated downstream — `requirements-dev.txt` pins `pip-tools==7.6.1`, `pip-audit==2.10.1` and `pyinstaller==6.19.0` (with `pyinstaller-hooks-contrib` pinned transitively) with hashes so subsequent environments are reproducible. Rationale: dev-only tooling, never shipped, run by the operator |
| T-08-08 | Repudiation | Lock regenerated with an untraceable command | mitigate | `CUSTOM_COMPILE_COMMAND` is set so the header records the exact, reproducible `pip-compile` invocation; acceptance criteria assert the header string is present and that no spurious `--no-index` appears |
| T-08-09 | Denial of Service | pip-tools downloading artifacts until the disk fills (`OSError(28)`) | mitigate | `TMP`/`TEMP`/`TMPDIR` pointed at a ≥10 GB drive; a pure-PyPI lock needs no wheel downloads at all |
| T-08-10 | Information Disclosure | Lock files leaking secrets | accept | Lock files contain only public package names and public digests; `app_config.json` (the only secret) is gitignored and untouched. Rationale: no secret material is in scope |
</threat_model>
