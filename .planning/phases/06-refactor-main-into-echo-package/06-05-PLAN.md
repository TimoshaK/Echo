|----------|-------------|
| OS → application entry point | `py -3 main.py` / `py -3 -m echo` resolve imports from the working directory |
| Repository root ↔ package | Config discovery crosses from `echo/` up to the repo root |
| Build tooling → source tree | `main.spec` drives PyInstaller's module analysis |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | T (Tampering) | config split-brain after `app_config.py` deletion | mitigate | The deletion is atomic with the launcher rewrite (the file's only importer). Task 1 asserts no `app_config` reference remains in `main.py`; Task 2 asserts no other source file mentions `app_config` and that `CONFIG_PATH.parent` is the repository root. |
| T-06-22 | E (Elevation of Privilege) | `python -m echo` / `python main.py` import resolution | accept | Both entry points import from the repository's own package only; `sys.path` is the operator's working directory, which is the standard assumption for a local desktop app. No `eval`, no dynamic module loading. |
| T-06-23 | I (Information Disclosure) | `main.spec` packaging | mitigate | `hiddenimports=['echo']` bundles only first-party modules. `app_config.json` is deliberately not listed in `datas`, so the API key is not baked into a distributable artifact. |
