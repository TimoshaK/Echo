--------------------------------------------------------------------------------
 0. КРАТКО: ОБЩАЯ КАРТИНА
--------------------------------------------------------------------------------

Приложению нужны РОВНО ТРИ "внешние" вещи, которых нет в самом репозитории:

   1) Python          — интерпретатор, на котором запускается программа
   2) pip-пакеты      — библиотеки (openai-whisper, torch, numpy и др.)
   3) FFmpeg          — отдельный системный бинарник (НЕ ставится через pip)
   +  модель base.pt  — скачивается автоматически при первом запуске

Схема "кто за что отвечает":

   [аудиофайл .mp3/.m4a/.wav] 
            │
            ▼
   ┌──────────────────┐   декодирует звук в сырые числа
   │     FFmpeg       │   (моно, 16000 Гц)
   │ (системный .exe) │
   └──────────────────┘
            │  сырые сэмплы (PCM)
            ▼
   ┌──────────────────┐   превращает звук в "мел-спектрограмму"
   │ openai-whisper   │   и прогоняет через нейросеть
   │   (Python)       │
   └──────────────────┘
            │
            ▼
   ┌──────────────────┐   считает матричные операции на CPU/GPU
   │     torch        │
   └──────────────────┘
            │
            ▼
        [текст транскрипции]

 1. СЛОВАРЬ ТЕХНИЧЕСКИХ ТЕРМИНОВ
--------------------------------------------------------------------------------

Понадобится для понимания остального текста.

  Интерпретатор
      Программа, которая читает и выполняет код на Python. Файл-скрипт
      (.py) сам по себе не запускается — его исполняет интерпретатор
      `python` / `py`.

  pip
      Менеджер пакетов Python. Команда `pip install <имя>` скачивает
      библиотеку с сайта PyPI и устанавливает её.

  PyPI
      Python Package Index (https://pypi.org) — официальный каталог
      Python-библиотек.

  Библиотека / пакет
      Набор готового кода, который подключается к программе через `import`.

  Виртуальное окружение (venv)
      Изолированная папка с Python-пакетами конкретно для этого проекта.
      Чтобы библиотеки одного проекта не конфликтовали с другим.

  Бинарник / исполняемый файл
      Готовая программа в машинных кодах (.exe на Windows). FFmpeg —
      именно такой: это не библиотека Python, а отдельная программа.

  PATH
      Переменная окружения со списком папок, где система ищет программы
      по имени. Если написать `ffmpeg`, Windows ищет ffmpeg.exe в папках
      из PATH. Не добавить папку в PATH = "ffmpeg не найден".

  Контейнер (формат файла)
      "Обёртка" файла: .mp3, .m4a, .wav, .ogg, .webm. Внутри лежит один
      или несколько потоков (аудио/видео/субтитры).

  Кодек
      Способ сжатия звука: MP3, AAC, Opus, Vorbis, FLAC, PCM. Контейнер
      говорит "где", кодек — "как сжато".

  Демультиплексирование (demux)
      Извлечение нужного потока из контейнера. Для нас — вытащить аудио
      из файла.

  Декодирование
      Превращение сжатого звука в "сырые" числа (сэмплы).

  Ресемплинг (resample)
      Изменение частоты дискретизации. Whisper требует ровно 16000 Гц.

  Даунмикс (downmix)
      Сведение нескольких каналов (стерео) в один (моно). Whisper ест моно.

  Сэмпл
      Одно измеренное значение громкости в момент времени.

  PCM / s16le
      "Сырой" несжатый звук. s16le = знаковые 16-битные целые, порядок
      байтов little-endian.

  Нейросеть (нейронная сеть)
      Математическая модель, обученная на данных. Здесь — сеть Whisper,
      которая переводит звук в текст.

  Тензор
      Многомерный массив чисел (в torch). Звук превращается в тензор.

  ASR (Automatic Speech Recognition)
      Автоматическое распознавание речи. То есть "перевод аудио в текст".

  CUDA / GPU
      Технология NVIDIA для вычислений на видеокарте. Ускоряет нейросети,
      но требует GPU NVIDIA и ~2.7 ГБ дополнительных DLL.

  JIT (Just-In-Time компиляция)
      Компиляция кода "на лету" во время выполнения (numba). Ускоряет
      числовые расчёты.

  subprocess (дочерний процесс)
      Когда Python запускает другую программу как отдельный процесс.
      Именно так whisper запускает ffmpeg.

  Wheel (.whl)
      Готовый к установке архив Python-пакета.

  PyInstaller
      Инструмент, который "заворачивает" Python-программу вместе с
      зависимостями в standalone-папку/.exe.

  onefile / onedir
      Режимы PyInstaller: один файл .exe ИЛИ папка с exe + библиотеками.


--------------------------------------------------------------------------------
 2. ПОТОК ДАННЫХ: ЧТО ПРОИСХОДИТ ПРИ ТРАНСКРИБАЦИИ
--------------------------------------------------------------------------------

Когда пользователь нажимает "START TRANSCRIPTION", по шагам:

  1. Приложение передаёт путь к выбранному файлу (например, lecture.mp3)
     в библиотеку openai-whisper.

  2. Whisper вызывает функцию load_audio(), которая ЗАПУСКАЕТ FFmpeg
     как отдельный процесс с такими аргументами:

         ffmpeg -i lecture.mp3 -f s16le -ac 1 -acodec pcm_s16le -ar 16000 -

     Расшифровка аргументов:
         -i lecture.mp3      входной файл
         -f s16le            выходной формат — сырой 16-битный PCM
         -ac 1               один канал (моно)
         -acodec pcm_s16le   кодек — PCM, знаковый 16-бит little-endian
         -ar 16000           частота дискретизации 16000 Гц
         -                   вывод в stdout (не в файл)

  3. FFmpeg внутри себя:
         • демультиплексирует контейнер (достаёт аудиопоток),
         • декодирует кодек (MP3/AAC/Opus/... → сэмплы),
         • сводит в моно,
         • ресемплит в 16000 Гц,
         • отдаёт сырые байты обратно в Python.

  4. Python превращает байты в массив чисел float32 в диапазоне [-1, 1]
     (каждый int16 делится на 32768).

  5. Whisper строит по этому массиву "мел-спектрограмму" — картинку
     звука — и прогоняет её через нейросеть (torch выполняет вычисления).

  6. На выходе — текст. У каждого фрагмента есть таймкоды (start/end),
     которые приложение использует для формата .srt.

  7. FFmpeg после шага 3 БОЛЬШЕ НЕ НУЖЕН. Он — только "входной шлюз".

 4. КОМПОНЕНТ 2: PIP-ПАКЕТЫ (Python-библиотеки)
--------------------------------------------------------------------------------

Ставятся одной командой из файла requirements.txt:

    py -m pip install -r requirements.txt


 4.1 openai-whisper  —  ГЛАВНЫЙ ДВИЖОК
 --------------------------------------------------------------------------
 ЧТО ЭТО
     Официальная Python-реализация модели распознавания речи Whisper
     от OpenAI. Именно она превращает звук в текст.

 ЗАЧЕМ
     Это ядро приложения. Реализует:
         • загрузку модели (whisper.load_model("base")),
         • транскрибацию (model.transcribe(...)),
         • автоматическое определение языка,
         • разбивку на сегменты с таймкодами (для .srt).

 КАК ИСПОЛЬЗУЕТСЯ
     Программисту — ничего делать не нужно: библиотека вызывается из
     main.py. Ей, однако, ТРЕБУЕТСЯ системный FFmpeg (см. раздел 5).

 Источник: https://pypi.org/project/openai-whisper/


 4.2 torch  —  ВЫЧИСЛИТЕЛЬНЫЙ ДВИЖОК
 --------------------------------------------------------------------------
 ЧТО ЭТО
     PyTorch — библиотека для нейросетей. Выполняет "математику" модели.

 ЗАЧЕМ
     Whisper — это нейросеть, а нейросети = умножение больших матриц.
     torch делает это быстро (на CPU или на GPU через CUDA).

 КАК ИСПОЛЬЗУЕТСЯ
     Устанавливается автоматически как зависимость.
     Есть ДВА варианта:
         • CPU-only  (~118 МБ) — считает на процессоре, медленнее;
         • CUDA      (~2.8 ГБ) — считает на видеокарте NVIDIA, быстрее.
     Для обычного ПК без NVIDIA подходит CPU-вариант.

 Источник: https://pypi.org/project/torch/


 4.3 Вспомогательные пакеты (ставятся АВТОМАТИЧЕСКИ)
 --------------------------------------------------------------------------
 Их не нужно указывать руками — они приходят как зависимости whisper.
 Но знать о них полезно, потому что именно они раздувают размер сборки.

   numpy        — массивы чисел. Звук хранится как массив numpy.
   numba        — JIT-компиляция, ускоряет расчёты в whisper.timing.
   llvmlite     — внутренности numba (сам по себе крупный, ~115 МБ).
   tiktoken     — токенизатор (разбиение текста на "токены").
   tqdm         — прогресс-бар (используется при скачивании модели).
   more-itertools — вспомогательные утилиты.

 Источники: pypi.org/project/<numpy|numba|llvmlite|tiktoken|tqdm>


 4.4 srt  —  ОБЪЯВЛЕН, НО НЕ ИСПОЛЬЗУЕТСЯ
 --------------------------------------------------------------------------
 В requirements.txt есть пакет `srt`, но код его НЕ импортирует.
 Субтитры .srt приложение формирует вручную (функция _srt_content).
 Вывод: пакет можно убрать из requirements.txt (лишняя зависимость).

 5. КОМПОНЕНТ 3: FFMPEG  —  САМЫЙ ВАЖНЫЙ И САМЫЙ НЕПОНЯТНЫЙ
--------------------------------------------------------------------------------

 5.1  ЧТО ЭТО
 --------------------------------------------------------------------------
 FFmpeg — это отдельная (НЕ Python) программа-мультимедийный фреймворк.
 Она умеет декодировать, кодировать, конвертировать, резать, склеивать,
 фильтровать и воспроизводить практически любой медиаформат.

 Это не библиотека Python и НЕ ставится через pip. Это системный
 бинарник (ffmpeg.exe), который должен быть доступен по имени `ffmpeg`.

 Более узкие компоненты внутри FFmpeg:
     libavformat  — работа с контейнерами (mp3/mp4/webm и т.д.)
     libavcodec   — кодеки (MP3/AAC/Opus/...)
     libswresample— ресемплинг и сведение каналов
     (всего есть ещё libavfilter, libavutil, libswscale, libavdevice)


 5.2  ЗАЧЕМ ОН НУЖЕН В ECHO
 --------------------------------------------------------------------------
 Whisper НЕ УМЕЕТ САМ ОТКРЫВАТЬ .mp3, .m4a, .webm и др.
 Он умеет работать ТОЛЬКО с сырым сигналом: моно, 16000 Гц, PCM.

 FFmpeg — это "переводчик" между форматами пользователя и тем, что
 понимает нейросеть. Без него транскрибация падает с ошибкой
 "Failed to load audio" ещё ДО того, как включится нейросеть.

 Технически это выглядит так (упрощённо, из исходника whisper):

     subprocess.run(["ffmpeg", "-i", file, "-f", "s16le",
                     "-ac", "1", "-ar", "16000", "-"])

 То есть Python порождает дочерний процесс ffmpeg и читает его вывод.

 ПОЧЕМУ НЕ ЧЕРЕЗ PIP
     Потому что это системная программа, а не Python-пакет. Whisper
     официально требует, чтобы команда `ffmpeg` была доступна в PATH.
     Следствие: установка FFmpeg — отдельный, обязательный шаг.


 5.3  УМЕЕТ ЛИ FFMPEG ТРАНСКРИБИРОВАТЬ?  (важное уточнение)
 --------------------------------------------------------------------------
 КОРОТКИЙ ОТВЕТ: НЕТ.

 FFmpeg — про "транспорт" и "формат" медиа. В его списке возможностей
 нет Speech-to-Text. Он декодирует звук, но не распознаёт речь.

 Тонкость: с августа 2025 в "full"-сборках FFmpeg появилась опция
 whisper.cpp (аудиофильтр `whisper`). Но:
     • это только "full"-сборки, не "essentials";
     • на типовых сборках фильтр отключён (--disable-whisper);
     • Echo на это не полагается вообще.

 Запомните разделение этапов:
     FFmpeg  = ДЕКОДИРУЕТ звук (формат → числа)
     Whisper = РАСПОЗНАЁТ речь (числа → текст)
     Это два РАЗНЫХ этапа и два РАЗНЫХ инструмента.


 5.4  ОТКУДА БРАТЬ FFMPEG ДЛЯ WINDOWS
 --------------------------------------------------------------------------
 Официального .exe для Windows на ffmpeg.org нет (там только исходники).
 Берут готовые сборки:

   • BtbN/FFmpeg-Builds (GitHub Releases)
       https://github.com/BtbN/FFmpeg-Builds/releases
       Файл: ffmpeg-master-latest-win64-gpl.zip  (есть постоянный "latest")
       Статический .exe, автосборки ежедневно. Архив ~100+ МБ.

   • gyan.dev (CODEX FFMPEG)
       https://www.gyan.dev/ffmpeg/builds/
       "release essentials" = ~34 МБ (7z) / ~109 МБ (zip).
       Для Echo ДОСТАТОЧНО essentials (нужен только декодер+ресемплер).

   • Менеджеры пакетов (проще всего):
       winget install "FFmpeg (Essentials Build)"
       choco install ffmpeg
       scoop install ffmpeg

 Установка вручную (без менеджера):
     1. Скачать архив (BtbN или gyan essentials).
     2. Распаковать, например, в C:\ffmpeg\  (внутри будет bin\ffmpeg.exe).
     3. Добавить C:\ffmpeg\bin в переменную PATH.
     4. Открыть НОВОЕ окно терминала (старое не увидит обновлённый PATH).
     5. Проверить:   ffmpeg -version

 ЦЕЛОСТНОСТЬ: на gyan.dev рядом с архивом лежит .sha256 — можно сверить.


 5.5  АНАЛОГИ FFMPEG (как аудио-декодера)
 --------------------------------------------------------------------------
     FFmpeg CLI (текущий выбор)
         Системный бинарник. Плюс: все форматы, ноль изменений кода.
         Минус: отдельный шаг установки.

     PyAV
         Python-биндинги к FFmpeg-библиотекам. Системный FFmpeg НЕ нужен
         (всё внутри wheel). Именно так работает faster-whisper.
         Минус: надо переписывать загрузку аудио.

     soundfile (libsndfile)
         Простой, но НЕ читает MP3/AAC/M4A → форматы Echo не покрывает.

     pydub
         Обёртка, которая ВСЁ РАВНО вызывает ffmpeg. Зависимость не убирает.

     miniaudio
         Лёгкий декодер (mp3/flac/wav), но без m4a/aac/ogg.

 5.6  АНАЛОГИ САМОГО ДВИЖКА ТРАНСКРИБАЦИИ (не FFmpeg!)
 --------------------------------------------------------------------------
     faster-whisper   — до 4× быстрее, меньше памяти, и убирает
                        FFmpeg-зависимость (через PyAV). Лучший кандидат
                        на будущее. Другой API.
     whisper.cpp      — очень лёгкий (C/C++), offline. Но CLI принимает
                        только WAV → FFmpeg всё равно нужен.
     Vosk             — крошечные модели (~50 МБ), streaming, offline.
                        Точность ниже, чем у Whisper.
     wav2vec2         — хорош на чистом аудио, но нет таймкодов "из коробки".
     Коммерческие API — OpenAI/Deepgram/AssemblyAI/Google. Платно, нужен
                        интернет, аудио уходит на сторону (приватность).

 ВЫВОД: для Echo движок менять не нужно. openai-whisper уже интегрирован,
 покрывает требования. faster-whisper — вариант следующего этапа.

 6. КОМПОНЕНТ 4: МОДЕЛЬ base.pt
--------------------------------------------------------------------------------

ЧТО ЭТО
    Файл с "обученными весами" нейросети Whisper (вариант "base").
    Размер ~138.5 МБ.

ЗАЧЕМ
    Модель — это "мозг". Без файла весов распознавать нечем.
    "base" — компромисс между скоростью и точностью.

КАК ИСПОЛЬЗУЕТСЯ
    При первом нажатии "START TRANSCRIPTION" библиотека whisper
    автоматически скачивает base.pt в кэш:
        Windows: %USERPROFILE%\.cache\whisper\
    Нужен интернет (только в первый раз).

    ВАРИАНТ для offline-сборки: встроить base.pt в бандл (--add-data),
    тогда интернет не потребуется, но сборка станет на 138.5 МБ больше.

Источник (автоматически):
    https://openaipublic.azureedge.net/main/whisper/models/.../base.pt

 7. ОПЦИОНАЛЬНО: PyInstaller (сборка .exe)
--------------------------------------------------------------------------------

ЧТО ЭТО
    Инструмент, который упаковывает Python-программу вместе со всеми
    библиотеками в standalone-сборку (папку или один .exe), чтобы у
    пользователя не было Python/pip.

ЗАЧЕМ
    Чтобы отдать приложение человеку, у которого нет Python.

КАК ИСПОЛЬЗУЕТСЯ
    Устанавливается отдельно (dev-инструмент):  pip install pyinstaller
    Затем:  pyinstaller Echo.spec

ВАЖНЫЕ ТОНКОСТИ ДЛЯ ЭТОГО ПРОЕКТА
    • torch/whisper тяжёлые. CUDA-вариант = ~3 ГБ. CPU-only = ~118 МБ.
    • Режим onedir (папка) лучше, чем onefile: onefile распаковывает
      сотни МБ во временную папку при КАЖДОМ запуске.
    • FFmpeg нужно ВСТРОИТЬ в бандл и добавить его папку в PATH на старте.
    • Модель base.pt — либо скачивать при первом запуске, либо встроить.
    • КОНФИГ: сейчас app_config.py пишет файл рядом с кодом; в onefile
      это указывает во временную папку → настройки/API-ключ теряются.
      Правильно: писать в %APPDATA%\Echo\config.json.
    • Для релиза — --windowed (без чёрного окна консоли).
    • UPX лучше отключить (может портить большие DLL torch).

 Текущая сборка в репозитории (build/, dist/, main.spec) — черновая:
 весит ~3 ГБ, console=True, без FFmpeg и модели. Для раздачи не годится.


--------------------------------------------------------------------------------
 8. УСТАНОВКА: ПОШАГОВО (Windows)

 СЦЕНАРИЙ A. Разработчик / запуск из исходников
 --------------------------------------------------------------------------
   0) Проверить Python:
          py --version            (ожидаем 3.10+)

   1) Получить код:
          git clone <repo-url> Echo
          cd Echo

   2) Виртуальное окружение:
          py -m venv .venv
          .\.venv\Scripts\Activate.ps1       (PowerShell)
          :: или .\.venv\Scripts\activate.bat (cmd)

   3) Python-библиотеки:
          py -m pip install --upgrade pip
          py -m pip install -r requirements.txt

   4) FFmpeg (обязательный системный шаг, pip его НЕ ставит):
          winget install "FFmpeg (Essentials Build)"
          :: либо choco install ffmpeg / scoop install ffmpeg
          :: либо вручную распаковать BtbN/gyan-сборку и добавить в PATH

   5) Проверить, что всё видно:
          ffmpeg -version
          py -c "import whisper, torch, numpy; print(torch.__version__)"

   6) Запуск:
          py main.py


 СЦЕНАРИЙ B. Конечный пользователь — из исходников
 --------------------------------------------------------------------------
   1) Установить Python с официального сайта
      (галочка "Add python.exe to PATH").
   2) Скачать архив с проектом, распаковать.
   3) В терминале в папке проекта:
          py -m pip install -r requirements.txt
          winget install "FFmpeg (Essentials Build)"
          py main.py
   4) При первой транскрибации модель base.pt (~138.5 МБ) скачается
      автоматически (нужен интернет).
   5) Настроить конспект: кнопка "API SETTINGS" → вставить API-ключ.
      По умолчанию: base URL https://openrouter.ai/api/v1,
      модель openai/gpt-4o-mini.


 СЦЕНАРИЙ C. Конечный пользователь — готовый .exe
 --------------------------------------------------------------------------
   Ничего ставить не нужно: Python, библиотеки, FFmpeg и (опционально)
   модель уже внутри папки. Пользователь просто запускает .exe.
   (Требует, чтобы такую сборку сначала собрали — см. раздел 7.)


--------------------------------------------------------------------------------
 9. ЧТО БЕЗ ЧЕГО НЕ РАБОТАЕТ (матрица зависимостей)
--------------------------------------------------------------------------------

   Без Python      → приложение вообще не запускается.
   Без pip-пакетов → ошибка import (нет whisper/torch).
   Без FFmpeg      → "Failed to load audio": нейросеть не получает звук.
   Без интернета   → первый запуск не скачает модель base.pt
                     (если она не встроена в сборку).
   Без API-ключа   → транскрибация работает, а конспект (LLM) — нет.
                     Ключ вводится в "API SETTINGS".


--------------------------------------------------------------------------------
 10. ЧАСТЫЕ ВОПРОСЫ
--------------------------------------------------------------------------------

 В: Почему FFmpeg нельзя просто поставить через pip?
 О: Это системная программа, а не Python-библиотека. Whisper запускает её
    как внешний процесс и ищет по имени `ffmpeg` в PATH.

 В: FFmpeg сам делает транскрибацию?
 О: Нет. Он декодирует звук. Распознаёт речь отдельная нейросеть Whisper
    в Python/torch.

 В: Нужен ли FFmpeg, если аудио уже в WAV?
 О: Формально whisper всё равно зовёт ffmpeg. WAV он тоже обрабатывает
    через ffmpeg, так что зависимость остаётся.

 В: Почему сборка .exe такая огромная?
 О: Основной вес — torch. CUDA-версия добавляет ~2.7 ГБ. CPU-only сильно
    меньше (~118 МБ). Плюс llvmlite (~115 МБ) и другие.

 В: Можно ли обойтись без FFmpeg в будущем?
 О: Да — переход на faster-whisper (внутри PyAV) убирает системную
    зависимость FFmpeg. Это кандидат на отдельный этап развития.

 В: Что такое "конспект" и при чём тут OpenRouter?
 О: Конспект — краткое содержание транскрипции. Его делает внешняя
    LLM (языковая модель) по HTTP-запросу. OpenRouter — шлюз, через
    который можно обращаться к разным моделям по одному ключу. Это НЕ
    FFmpeg и НЕ Whisper — отдельный, опциональный этап.
